# 5. Release

Publish the backend and frontend packages to a GitHub Release (one wheel and one sdist each, never a
package index), bump the add-on version and deploy the documentation to GitHub Pages.

## Before you start

Once, in the repository settings:

- Actions → General → Workflow permissions: **Read and write**. The workflow declares `permissions: {}`
  and grants `contents: read` to the checks, `contents: write` to the release and docs jobs.
- Pages → Deploy from a branch → `gh-pages`.
- Squash merging enabled, so the PR title decides the version
  ([commit convention](3.conventions.md#commit-convention)).

Locally, install the tooling and log in:

```bash
make install-dev
gh auth login
```

Credentials resolve from `GH_TOKEN` (environment or local `.env`), then the token saved by
`gh auth login`, then a hidden terminal prompt. Never print credentials.

## What a release does

1. **Validate** the source: `main` or `dev`, clean tree, HEAD equal to the fetched origin tip, and in
   CI HEAD equal to the tested `GITHUB_SHA`.
2. **Version** with semantic-release from Conventional Commits. Its build hook locks and builds every
   package before anything is committed, tagged or published.
3. **Commit, tag and push** `chore(release): personal-app-v<version> [skip ci]`. The commit updates
   the three `pyproject.toml` versions, `config.yaml` (the version Home Assistant offers as an update),
   `uv.lock` and `CHANGELOG.md`.
4. **Upload** the wheel and sdist of both packages to the GitHub Release.
5. **Deploy docs** from the release tag, on a stable `main` release only.

Never edit a version, the changelog or a tag by hand. Tags look like `personal-app-vX.Y.Z`
(`personal-app-vX.Y.Z-rc.N` on a `dev` branch); Python artifact names use `X.Y.ZrcN`.

## Automatic release (CI)

`release.yml` runs on a push to `main` (or `dev`) that touches `addons/personal-app/**`, and on manual
dispatch. `quality-checks` is the gate; if it fails or is skipped, nothing is versioned or published.
The release commit carries `[skip ci]`, so its own push does not re-run the gate. Docs-only and
`chore` commits bump no version.

A guard step skips the release when nothing under `addons/personal-app/` changed since the last
`personal-app-v*` tag, because semantic-release reads the commits of every add-on.

## Manual release (local)

```bash
make check
make release
```

It versions, builds and uploads the full wheel/sdist set, and asks you to type `yes`. It changes Git
and GitHub; coding agents need explicit per-action approval. `make release-status` reports branch,
tree, origin sync, tag and GitHub release without changing anything; run it when a release refuses.

Publish docs separately from the clean released tag with `make deploy-doc-gh`, which pushes `gh-pages`
and needs separate authorization.

### The guard

The release refuses unless the branch is `main` or `dev`, the tree is clean (the whole repository, not
just this folder) and HEAD equals `origin/<branch>`:

- **Dirty tree** from hook fixes or a stale lock: commit it first, as `chore(...)`.
- **Not in sync:** `git pull --rebase` when behind, `git push` when ahead.

## Recover an interrupted release

Each stage is re-runnable and stops before publishing on a bad precondition: a failed build hook
(`uv lock && git add uv.lock && make build-package`) stops everything before any commit, tag or upload,
and `make release-assets` refuses when the tag is not at HEAD or a package has no wheel/sdist pair.

- **CI:** rerun the failed job while its tested source still matches the release.
- **Same branch, locally:** `make release` stops without uploading when nothing is left to publish.
- **From a clean checkout of the exact tag:** `make build-package`, then `make release-assets`.
- **Newer commits exist:** let their own workflow release them; never rebuild an older release from later source.

## Verify the release

- `gh release view personal-app-vX.Y.Z --json assets,isDraft` lists one wheel and one sdist per
  package, with `isDraft: false`.
- `config.yaml` on `main` carries the new version, and Home Assistant offers the update.
- Stable only: `gh-pages` has a new commit and the site shows the new version.

## Fix a bad release

Fix forward: revert on `main` and let the next patch release carry the fix. Do not move, delete or
re-create a published tag.
