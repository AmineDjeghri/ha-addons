# 2. Project structure

Where things are, and where to add yours.

## Layout

A uv workspace with two packages that share one version and one git tag, packaged as a Home Assistant add-on.

```text
pyproject.toml          workspace root: shared dev/docs tools, ruff, pytest, semantic-release, commitizen
backend/                package personal-app-backend (FastAPI)
  pyproject.toml        backend dependencies
  src/personal_app_backend/
    app.py              FastAPI application
    api/routes/metrics.py  host metrics route
    backend_settings.py settings (pydantic-settings, .env) and the loguru logger
frontend/               package personal-app-frontend (NiceGUI)
  src/personal_app_frontend/
    main.py             NiceGUI application
    components/metrics.py  metrics component
    frontend_settings.py
tests/unit/             backend, docs and release tooling tests
scripts/                commit parser, release artifact checks and workspace docs generators
makefiles/              one .mk per concern, included by Makefile
docs/developer/         this guide
config.yaml build.json  Home Assistant add-on definition (version written by semantic-release)
Dockerfile run.sh       add-on image and its startup script
properdocs.yml          documentation site (MkDocs Material)
CHANGELOG.md            written by semantic-release, never by hand
```

The repository root (`../../`) holds what every add-on shares: `.pre-commit-config.yaml`, `.github/`
(workflows, Renovate, templates) and `AGENTS.md`.

## Where to add things

| Task             | Where                                            | Help                                          |
| ---------------- | ------------------------------------------------ | --------------------------------------------- |
| a backend route  | `backend/src/personal_app_backend/api/routes/`   | [Add a backend route](#add-a-backend-route)   |
| a setting        | `backend_settings.py` or `frontend_settings.py`  | [Add a setting](#add-a-setting)               |
| an add-on option | `config.yaml` (`options`, `schema`) and `run.sh` | [Add an add-on option](#add-an-add-on-option) |
| a dependency     | `uv add --package <package> <pkg>`               | [Add a dependency](#add-a-dependency)         |
| a make target    | `makefiles/<concern>.mk` with a `## description` | —                                             |

## Add a setting

1. Add a field to the `ApplicationSettings` class in `backend_settings.py` (or
   `frontend_settings.py`). A secret is a `SecretStr`.
2. Add it, with a safe example value, to `.env.example`.
3. Read it through the module-level `settings` object.

## Add an add-on option

1. Add the option and its type to `options` and `schema` in `config.yaml`.
2. Export it in `run.sh` with `bashio::config`, using the setting's environment variable name.
3. Add the setting as above, so a local `.env` and the add-on behave the same.

## Add a backend route

1. Add the route in `backend/src/personal_app_backend/api/routes/` (an `APIRouter`).
2. Include the router in `app.py`.
3. Add isolated API tests in `tests/unit/backend/`. The route appears in `/docs` automatically.

## Add a dependency

`uv add --package personal-app-backend <pkg>` (or `--package personal-app-frontend`), then
commit `uv.lock`. The `Dockerfile` installs from `uv.lock` with `--frozen`.
