# 4. Testing

Run the offline tests during development and the full gate before a pull request.

## Before a pull request

Complete [setup](1.setup.md), then run:

```bash
make check
```

`make check` runs `pre-commit-status`, `pre-commit`, `test-all` and `docs-build` (it first warns if the
Git hooks are missing). `test-all` runs the unit tests, then builds both wheels and installs them in a
throwaway environment to check that they import. There are no integration tests yet.

## Focused checks

| Command                  | Scope / requirement                                            |
| ------------------------ | -------------------------------------------------------------- |
| `make check`             | `pre-commit-status`, `pre-commit`, `test-all` and `docs-build` |
| `make test-local`        | Unit tests only                                                |
| `make test-all`          | Every software suite, including the built-wheel smoke test     |
| `make pre-commit`        | Static hooks; `FILES="path/a path/b"` selects files            |
| `make pre-commit-status` | Warn when the Git hooks are not installed                      |
| `make docs-build`        | Strict docs build only                                         |
| `make build-package`     | Verify the backend/frontend wheel and sdist sets               |
| `make docker-build`      | Build the add-on image (requires Docker)                       |

Tests use `N=4` workers by default; use `N=0` for serial diagnostics. Focused targets accept `ARGS`
filters (`make test-unit ARGS="-k release"`); `test-all` rejects them.
Unit tests and synthetic artifacts do not prove a container or a Home Assistant install works.

## Writing tests

| Folder                | Tests                                     |
| --------------------- | ----------------------------------------- |
| `tests/unit/backend/` | Settings and isolated API checks          |
| `tests/unit/docs/`    | API reference generation                  |
| `tests/unit/release/` | Release tooling, with fake git, uv and gh |

Parallel tests share no state. Release tooling tests use isolated command substitutes and never publish.

## CI

`ci.yml` and `release.yml` run the reusable `quality-and-tests.yml`: pre-commit, then `make test-all`,
only for changes under `addons/personal-app/`. See [5. Release](5.release.md).

## Static and documentation hooks

Hooks check formatting and lint (Ruff), syntax and whitespace, secrets, Markdown and spelling, the
lockfile and the strict docs build, workflow syntax (actionlint) and workflow security (zizmor).
Commitizen runs only at the commit-msg stage. They live in the repository-root
`.pre-commit-config.yaml`, scoped per add-on. `make install-dev` installs the Git hooks in a checkout
(not in CI); `make pre-commit` only runs them.
